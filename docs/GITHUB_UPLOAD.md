# 上传 GitHub：只上传这份主方法源码

建议仓库名：`PAMFN-Ordered-EU`。这是描述性名称，不替你确定论文正式标题。

## 上传前

1. 解压 `PAMFN_Ordered_EU_paper_source_20261005.zip`，进入里面的 `PAMFN-Ordered-EU` 目录。不要把整个研究工作区、56份旧bundle或444MiB的全资料包上传。
2. 先阅读根README，再运行 `python checks/verify_source.py`。
3. 这是正常具名源码包，不是匿名投稿包。论文尚未公开时，可先建Private仓库，待导师/共同作者同意再公开。
4. 核对作者信息、公开许可与预训练数据授权。本包保留上游MIT声明，但没有擅自给你新增代码选择一个开源许可证，也没有虚构作者或论文DOI。

## 网页上传

GitHub新建空仓库后使用“Add file → Upload files”，上传解压目录中的文件/目录，保留目录层级。不要只把整个ZIP当作源码上传。文件较多时建议用Git客户端提交整个目录，避免网页上传漏文件。

## Git客户端上传

在这份解压目录中初始化一个新的仓库，而不是从整个研究工作区推送旧历史。使用你自己新建仓库的实际地址配置remote，再提交、推送。这个资料包本身不含外层`.git`，不会自动关联、修改或推送现有远程仓库。

`.gitattributes`刻意关闭自动换行转换，防止Windows提交后把已冻结源码的SHA256改掉。首次克隆后再次运行完整性检查；正常Git提交不会改变历史trainer commit的含义。

## 不要上传

- 实验产生的`results/`、`model.pth`、`*.pt`、特征、原视频、环境目录。
- 你本地的`runtime.env`、密码、token、SSH密钥。
- `reproduction/v29/v17_history.zip`原始历史运行包（包含运行记录，应另行审阅后再决定如何发布）。
- 本机绝对路径下的其他私人资料。

这些常见输出已加入`.gitignore`。两个约1MiB的`qmd_supp_v17_full.bundle`是保留精确历史代码所需的小型源码资产，允许提交；它们包含上游及历史代码身份/记录，不是匿名材料。其已知高置信度凭证模式已扫描，但这不能代替你在公开前的人工检查。
